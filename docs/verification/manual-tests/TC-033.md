## Purpose

Check, end to end on the deployed site, that a user can upload a resume and get their profile filled in (education, work experience, projects, skills, socials), and that the parsed skills feed job compatibility. The automated tests call the Flask app directly, so they cannot catch problems in how the deployed site routes requests from the browser to the backend. This test covers that gap.

## Procedure

1. Open https://jobrec.thecoolsite.org and log in.
2. Go to the Profile page. Open the browser developer tools (Cmd + Option + I) on the Console tab.
3. Click **Upload resume** and choose the PDF resume.
4. Click **Submit** and wait about 30 seconds.
5. Check the Profile page for the parsed education, work experience, projects, skills and socials.
6. Go to the Jobs page and check the compatibility scores.
7. Check the Console for failed requests.

## Expected result

- The upload request succeeds.
- After processing, the Profile page lists the skills and other details from the resume.
- The Jobs page shows non-zero compatibility for jobs that match those skills.

## Actual result

## Analysis

- The backend defines the route `@app.route("/upload", methods=["POST"])` in `app/jobrec/app.py`, and the frontend calls `fetch("/upload")` in `frontend/src/pages/Profile.jsx`. Both match on `main`.
- On the hosted site, requests under `/api/` reach the backend (the profile name, email and phone load from `GET /api/profile`), but `POST /upload` returns 404.
- In local development, `frontend/vite.config.js` proxies both `/api` and `/upload` to the backend. The likely cause is that the hosted deployment forwards only `/api/*` to Flask, so `/upload` never reaches it. Not yet confirmed against the server configuration.
- Suggested fix: move the route to `/api/upload` in both `app.py` and `Profile.jsx` (and the Vite proxy), so it follows the same path as every other backend route; or add `/upload` to the hosted routing.

## Notes and defects

- Defect filed: #176 (resume upload returns 404 on the hosted site).
- Impact: new users cannot fill their profile from a resume, so every recommendation shows 0% compatibility. This blocks the main user flow tested in UAT.
