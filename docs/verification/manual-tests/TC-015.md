## Purpose

The automated tests replay saved Workday responses. This manual run checks the same paging logic against the real Workday sites, which can change their API without notice.

## Procedure

1. Take every Workday source listed in `app/jobrec/job_sources_demo.json` (NVIDIA, Salesforce, Intel, Adobe, Caterpillar).
2. For each site, build `WorkdayScraper(board, page_size=20, max_pages=5)` and record every page request (offset, postings returned, total the site reports).
3. Run `fetch_jobs()` and count the listings built and the distinct job ids among them.
4. Command, from `app/`:

   ```
   PYTHONPATH=. python ../docs/verification/manual-tests/scripts/run_manual_tests.py tc015
   ```

## Expected result

For a site with at least 100 open postings: exactly 5 pages requested at offsets 0, 20, 40, 60, 80; 20 postings per page; 100 listings built; 100 distinct ids (no posting repeated across pages).

## Notes and defects

- Workday no longer accepts 50 postings per page, the scraper's current default, and answers HTTP 400. This was found by the weekly NF-06 run and filed as [#148](https://github.com/Work-At-JobRec/JobRec/issues/148). The run above uses 20 per page, the value [PR #143](https://github.com/Work-At-JobRec/JobRec/pull/143) sets as the new default.
