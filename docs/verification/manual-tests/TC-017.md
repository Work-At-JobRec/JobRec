## Deviation from the written procedure

The inventory row asks for the deployed server. No deployed database is reachable outside Vercel, so the run used a PostgreSQL 16 container, the same database engine as production, and the exact command the host's scheduler will call. "Moving the clock forward a month" was done by setting every row's last-seen time 31 days back. Scheduling itself will be verified once pruning is scheduled on the deployment host ([#69](https://github.com/Work-At-JobRec/JobRec/issues/69)).

## Procedure

1. Start the database: `docker run -d --name jobrec-pg -e POSTGRES_USER=jobrec -e POSTGRES_PASSWORD=jobrec -e POSTGRES_DB=jobrec -p 5433:5432 postgres:16`.
2. Seed it (`scripts/tc017_seed.py seed`): 4 open listings scraped live from Palantir's Lever board, plus 4 closed ones (2 Lever posting ids and 2 Greenhouse job ids that the sources answer with "not found"). Every row is marked last seen 31 days ago.
3. Run the pruning command: `DATABASE_URL=postgresql+psycopg://jobrec:jobrec@localhost:5433/jobrec python -m jobrec.prune_jobs --delete`.
4. Verify (`scripts/tc017_seed.py verify`) and count rows with `psql`.

## Expected result

All 4 closed listings removed, all 4 open listings kept, 4 rows remain.

## Actual result

- Pruning checked 8 links: 4 closed and removed, 3 confirmed open, 1 undetermined (a Lever request timed out, so the listing was kept, as designed).
- 4 rows remain, all of them the open listings; none of the closed listings are present (`select count(*)` returns 4).
