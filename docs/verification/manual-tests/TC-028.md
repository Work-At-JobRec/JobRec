## System rule under test

A listing is identified by its source and the source's job id. Seeing the same listing again updates the stored row instead of adding a new one, and repeats inside one batch collapse to one row.

## Procedure

1. Start from the TC-027 database (609 rows: Figma, Palantir, Ramp).
2. Scrape the same three sources a second time into the same database and record inserted / updated / unchanged per source.
3. Query for any (source, job id) pair stored more than once.
4. Take one stored listing, change its title, and submit it twice in the same batch, as a repost would arrive.
5. Command, from `app/`:

   ```
   PYTHONPATH=. python ../docs/verification/manual-tests/scripts/run_manual_tests.py tc028 <TC-027 db path>
   ```

## Expected result

- Step 2: 0 inserted for listings already stored; row count grows only by listings newly posted between the runs.
- Step 3: no duplicated pairs.
- Step 4: 0 inserted, 1 updated, row count unchanged, stored title replaced by the new one.

## Actual result

| Step | Result |
| --- | --- |
| Repeat scrape | Figma 0 inserted / 140 unchanged; Palantir 0 / 299; Ramp 0 / 170 |
| Row count | 609 before, 609 after |
| Duplicated (source, job id) pairs | 0 |
| Changed listing sent twice | 0 inserted, 1 updated, 609 rows, title now ends in "(repost)" |
